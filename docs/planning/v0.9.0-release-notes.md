### New Features

- **LOD store — recommended, off by default** — LSS can keep a compressed copy of every LOD column it serves and answer repeat requests from it instead of re-reading and re-serializing chunks. On a warm store that is ~99% of requests, at roughly 80% less CPU per column. It is **off by default** only because it roughly doubles your world folder, which should be your decision rather than a surprise. Turn it on with `"lodStore": "full"` — that one key also enables the background warm-up that pre-fills it from your existing world. Bound it with `lodStoreMaxMB` if disk is tight; it is derived data, so deleting `<world>/lss-lod/` is always safe.
- **Lower CPU per served chunk** — LOD columns are now compressed once on the server and sent to every client as-is, instead of Minecraft's connection compression re-compressing them per player. Bandwidth is roughly unchanged; the saving is CPU on both ends.
- **Faster LOD streaming while you stand still** — the client requests the next batch as soon as the last one arrives, up to four times a second, instead of on a fixed one-second timer. While moving fast the rate stays near the old cadence by design.
- **Folia support on Minecraft 26.2** — Folia published its first 26.2 build, so the plugin loads on it again. Folia support remains **experimental**: single-player scenarios pass, concurrent multi-region play is still unvalidated.

### Configuration

- **Higher bandwidth defaults** — 25 MiB/s per player (was 20), 256 MiB/s total (was 100). Two settings also auto-size themselves now: set `diskReaderThreads` and `perDimensionTimestampCacheSizeMB` to `0` and LSS picks values from your hardware and LOD distance.
- **Upgrading keeps your existing settings** — every value already in your config file is preserved, so the new defaults and auto-sizing will **not** reach you. Delete `diskReaderThreads`, `perDimensionTimestampCacheSizeMB`, `bytesPerSecondLimitPerPlayer` and `bytesPerSecondLimitGlobal` from the file (or delete the file) to pick them up.
- **Retired settings** — `lodStore: "memory"`, `lodStoreMemoryMB`, `lodStoreBackfillTickCeilingMillis` and `syncOnLoadConcurrencyLimitPerPlayer` are gone. They are ignored and dropped from your file on the next save; nothing else in it is touched.

### Bug Fixes

- **Turning LSS off now really turns it off** — with `enabled: false` the server no longer creates LOD data or walks your region files.
- **Disabling background read priority no longer increases disk load** — setting `useBackgroundReadPriority` to `false`, which admins do when LSS reads compete with normal chunk loading, could give LSS *more* full-priority read threads than before.
- **Diagnostic traces stop when you disconnect** — `/lss trace` kept running across disconnects and server changes with no size limit, and produced unreadable output where a comma is the decimal separator.
- **Paper: compression no longer switches off after a reconnect** — a client reconnecting through the legacy-protocol fallback spent the rest of its session receiving uncompressed data.
