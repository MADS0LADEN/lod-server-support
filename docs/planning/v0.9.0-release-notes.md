### New Features

- **LOD chunks are now stored and served back instantly** — LSS keeps a compressed copy of every LOD column it serves in `<world>/lss-lod/`, so a returning player's view fills from the store instead of being re-read and re-serialized from region files. On the live test server 98.8% of a full session's columns came from the store. It is on by default (`lodStore`), and it is derived data — deleting `lss-lod/` is always safe.
- **Background store warming** — a low-priority walk pre-fills the store from your existing world so the first player to arrive already gets warm serves, instead of warming it only where people have walked. It yields to players and to tick health, pauses under load, and resumes where it stopped across restarts. On by default (`lodStoreBackfill`); a typical world finishes in about 20 minutes.
- **LOD data is now compressed on the wire** — columns ship zstd-compressed to clients that support it. A full measured session sent 1.38 GB where it previously sent 8.63 GB, a 6.25:1 reduction. Older clients keep receiving the uncompressed format automatically.
- **Faster LOD streaming while you stand still** — the client now re-scans as soon as the previous batch is answered rather than on a fixed one-second timer, up to four times a second, so terrain fills in noticeably quicker. While you are moving fast the rate stays closer to the old cadence by design — pushing it higher reintroduces the bandwidth spike that caused stalls during flight.
- **Folia support returns on Minecraft 26.2** — Folia published its first 26.2 build, so the plugin declares Folia compatibility again. Folia support remains **experimental**: single-player scenarios pass, but concurrent multi-region play is still unvalidated.

### Configuration

- **Better defaults out of the box** — LOD distance 256, per-player bandwidth 25 MiB/s, global bandwidth 256 MiB/s, and the LOD store and its warming both on.
- **Auto-sizing for two settings that were guesses** — `diskReaderThreads` and `perDimensionTimestampCacheSizeMB` now accept `0` to mean "work it out", sizing themselves from the detected disk-read path and your configured LOD distance. This is the new default.
- **Upgrading? Two things to know.** Your existing config file keeps every value already written in it, so the improved auto-sizing and the raised bandwidth limits will **not** reach you — delete `diskReaderThreads`, `perDimensionTimestampCacheSizeMB`, `bytesPerSecondLimitPerPlayer` and `bytesPerSecondLimitGlobal` from the file (or delete the file) to pick them up. The LOD store **does** turn on for you: expect the world folder to roughly double, set `lodStore` to `off` to opt out, or `lodStoreMaxMB` to bound it.
- **Raised limits for large servers** — the ceilings on per-player bandwidth, concurrent generation, timestamp cache size and store size were all too conservative and have been lifted. Defaults are unchanged by this.
- **Retired settings** — `lodStore: "memory"` and `lodStoreMemoryMB` are gone (a `"memory"` value now reads as `off`), along with `lodStoreBackfillTickCeillingMillis` and `syncOnLoadConcurrencyLimitPerPlayer`. Retired keys are ignored and dropped from your file on the next save; nothing else in it is touched.

### Bug Fixes

- **The LOD store size cap now works** — with `lodStoreMaxMB` set, the store used to evict almost everything it held and keep evicting, settling at about a seventh of the size you configured, and could end up permanently empty with its file stuck above the limit. Three separate faults combined to cause it; all are fixed, and a capped store now settles at the size you asked for.
- **Turning LSS off now really turns it off** — with `enabled: false`, the server still created the LOD store and walked every region file in the world, writing gigabytes for a feature that was switched off.
- **A rare stale-terrain fault in the store** — under heavy load, an edited chunk could briefly be served from the store in its pre-edit state, and would stay that way for that player until they edited the area again or rejoined.
- **The store no longer risks filling your disk** — the warming walk now stops with 2 GB free. On a size-limited host it could previously fill the volume, which broke Minecraft's own world saving before it affected LSS at all.
- **Large worlds no longer risk running out of memory when store data is discarded** — clearing a dimension's stored LOD (which can happen automatically when x-ray masking settings change) loaded every entry into memory at once.
- **Disabling background read priority no longer increases disk load** — setting `useBackgroundReadPriority` to `false`, which admins do precisely when LSS reads are competing with normal chunk loading, could give LSS *more* full-priority read threads than the old default.
- **Diagnostic traces stop when you disconnect** — `/lss trace` kept running across disconnects and server changes with no size limit, and produced unreadable output on systems that use a comma as the decimal separator.
- **Paper: compression no longer silently switches off after a reconnect** — a client that reconnected through the legacy-protocol fallback path would spend the rest of its session receiving uncompressed data.

### Performance

- **Much less disk work per served chunk** — warm serves come from the store as pre-built, pre-compressed data with no region-file read and no re-serialization. Measured server CPU per column fell 43% on warm serves and 27% on cold ones.
