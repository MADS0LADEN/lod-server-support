### Bug Fixes

- **Fixes a disconnect on slow connections** — joining through a slow or saturated link could kill the connection right after login with "Packet ... was larger than I expected": the client's legacy-server discovery could leave the server briefly speaking an older wire dialect just as the session started, and the first terrain packets then broke the connection. The client now re-confirms its protocol before requesting any terrain, and waits longer (10 seconds per step) before trying legacy protocols, so slow joins no longer trigger false legacy fallbacks. Fabric client.

### New Features

- **Far players** — see other players far beyond normal render distance as simple player models standing in your LOD terrain: positions, poses (sneak/glide/swim), equipment, name tags, and smooth motion including elytra dead-reckoning. On by default — including for servers upgrading from earlier versions (`farPlayers` mode `on`; `opt-in` and `off` available, and the exclude list/permission below give per-player control). Bandwidth cost is tiny — quantized positions, change-only equipment, names sent once. Players riding horses, boats, minecarts or any other vanilla entity render seated WITH their mount; mounts your client doesn't know (modded, other MC versions) show an unmounted player instead — never a crash. Prior art: the SeeU mod (MIT) — reimplemented natively in LSS with server-authoritative privacy. On Folia this is the largest new surface and Folia support remains **experimental**.
- **Far-player privacy controls** — server: the `farPlayers` mode, a `farPlayersExclude` name/UUID list, the Paper permission `lss.farplayers.hidden`, and vanish-plugin awareness on Paper (SuperVanish/PremiumVanish/EssentialsX "vanished" metadata honored; plugins hiding players only via `hideEntity` are not detected — use the permission or exclude list). Client: "Share My Position" (on by default — turn it off to stay invisible beyond normal render distance while connected through LSS). Players on older LSS or vanilla clients are visible targets with no client-side opt-out — the server-side controls are their protection.
- **SeeU coexistence** — if the SeeU mod is installed on the client, LSS stops drawing far players automatically (running both would show every distant player twice); set `farPlayersWithSeeU: true` or "Prefer LSS Far Players" in the Sodium screen to use LSS instead. Your own "Share My Position" setting still applies either way.
- **`/lss reset` client command** — wipes Voxy's LOD store AND the LSS cache for the current server in one step: LODs visibly disappear, then rebuild live as the server re-streams everything. Without an active LSS session it requires `/lss reset confirm`. Fabric client; needs Voxy 0.2.18+ for the full effect.
- **Runtime settings commands** — `/lsslod set <key> <value>` applies a config change immediately AND persists it (values clamp exactly like the config file; a `lodDistanceChunks` change is pushed to connected current-version clients live — older clients keep re-asking beyond a shrunk distance until they rejoin). `/lsslod set` lists the settable keys; `/lsslod help` (or bare `/lsslod`) shows the full verb list. On Folia (experimental) the change applies through the global tick, same as every other LSS operation there.
- **Backfill remaining estimate** — `/lsslod store backfill status` now shows a remaining regions/columns estimate for the background pre-warm walk. Fabric.

### Configuration

- **`lodDistanceChunks` default 512 → 300** — a mid-range default; the automatic timestamp-cache sizing follows it. Raise it freely on capable servers.
- **`dirtyBroadcastIntervalSeconds: 0` now disables dirty broadcasts** — previously 0 clamped to the fastest cadence. With 0, connected clients pick up terrain edits only on rejoin or their own re-requests; server-side freshness bookkeeping keeps running, so rejoins always see current terrain.
- **`maxConcurrentDiskReads`** — new key (default auto): caps concurrent expensive region-file reads so server CPU stays bounded independently of bandwidth. Store-served LODs never consume its capacity; auto = half the reader pool with the LOD store on, no limit with it off. Applies on all platforms including Folia (experimental).
- **Far-player keys** — server: `farPlayers`, `farPlayersUpdateIntervalTicks`, `farPlayersMaxDistanceBlocks` (default 2048), `farPlayersMinDistanceBlocks`, `farPlayersSendSpectators`, `farPlayersExclude`. Client: the Sodium "Far Players" page carries enable, "Share My Position", name tags, and the render-distance cap; the animation-distance cap and visibility-ring overrides live in `lss-client-config.json`.
- **Adaptive slow-connection pacing** — Two new mechanisms keep gameplay responsive when LODs saturate a slow or throttled connection (previously every action could lag by seconds). The CLIENT transfer governor notices its own ping rising while LOD downloads run slow and paces its requests below the link's capacity, recovering automatically when the connection clears (client config `enableAdaptiveTransferRate`, default on — works against older servers too). The SERVER ping backstop watches each player's ping and cuts LOD bandwidth to any player whose connection is drowning, old clients included (`enablePingBackstop`, default on, changeable live via `/lsslod set`). The `outboundBufferCeilingKB` AUTO mode from earlier v0.11.0 dev builds is removed — `0` means off again; explicit values remain a fixed manual ceiling.
- **LOD now yields to vanilla transport by default** — `lodYieldsToVanillaTransport` flips to `true`: while a player's connection is backed up, LSS skips its LOD sends for that tick so vanilla chunk packets go first (a starvation floor keeps LODs trickling; behind a proxy the gate is best-effort). Set `false` to restore the old always-send behavior.
- **Client cache moves to `.lss/`** — fresh installs keep the LSS column cache in a `.lss/` folder in the game directory; existing installs with `config/lss/cache/` keep using it, no migration needed.

### Performance

- **Disk-read CPU is now bounded independently of bandwidth** — the new disk-read concurrency gate stops cold-region reads from turning a raised bandwidth cap into an unbounded CPU bill; store-served columns bypass it entirely.
