  scope for this program run; everything up to and including the pre-flight,

  rows' final step.
- **2026-08-06**: program executed by Claude (autonomous session(s)); review rounds
  per mega plan §6.2 with the repo's 2–3-subagent budget.
- **2026-08-06 (A1 implementation decisions, tracer plan §1.4 lss block)**: three of
  the sketched `lss` fields had no server-side source and are shipped as follows
  (tracer plan §1.4 edited in the same commit — the §6.1 pair): `bw_window` →
  **`bw_total`** (cumulative per-player bytes; no per-player rolling window exists,
  and a different quantity gets a different name — the U-12 discipline); `proto` is
  **derived from the dialect rung** (v16→16, v18→18, else current) since protocol
  version is consumed at handshake and never stored; `since_s` reads a new
  diagnostics-only `AbstractPlayerRequestState.getCreatedAtMillis()` stamped at state
  creation (== registration).
- **2026-08-06 (A1 Tier 2 finding)**: the tracer plan's "hasClientLoaded() is true
  out of the box" holds at listener CONSTRUCTION but not after `placeNewPlayer`,
  which arms the 60-tick `clientLoadedTimeoutTimer`; a mock connection never confirms
  → every move swallowed. The gametests prime the listener reflectively
  (`primeListenerForMoves`: clear `awaitingPositionFromClient`, zero the timer, clear
  `waitingForRespawn`) — test-only, dev-runtime named mappings.
- **2026-08-07 (A1 review round, three Opus lenses — correctness+concurrency /
  pinned-decisions+fidelity / tests+bytecode)**: 1 MAJOR + 2 pin-gap MAJORs + ~17
  minors, ALL fixed same-day (plan edits paired below). Headline — **A-1/C-1 MAJOR,
  found independently by two lenses**: the `@At("HEAD")` inject ran on the NETTY
  event loop for every move packet (vanilla's `ensureRunningOnSameThread` is the
  method's first statement and re-dispatch-throws there), racing the gap clock
  (double-record → `move_gap_ms` measured the netty→main hop, structurally ~0 — the
  U-5 instrument dead on arrival), leaking swept per-player state via a netty-side
  `computeIfAbsent`, and corrupting the `restored` capture under packet pipelining.
  Fixed by retargeting the entry inject to INVOKE shift-AFTER the ensure call (runs
  exactly once, server thread) + an ASM pin that only argument plumbing precedes the
  ensure INVOKE. Pin-gap MAJORs: the rotation test could not distinguish the 2x cap
  from unbounded rotation (C-2 — now asserts drop counts + total surviving lines);
  the ring-flush-before-event ordering and FlightRing wrap-around were unpinned
  (C-3 — source-regex ordering pin + FlightRingTest). Plan-deviation pairs applied:
  `awaiting_tp` moved to flight rows (A-2 — structurally false at event sites),
  `expected_dist` → `expected_dist_sq` (B-6), per-boot rotation over a stale .1
  (B-5), `logged_wrongly` rejected-only (B-2), `restored` optional when the entry
  capture never ran (C-10). Also: adapter probes re-wrapped whole-body catch-all
  (A-3), single `isActive` read per snapshot (A-4), writer counts rows on WRITE with
  IOException/interrupt drain+cap-latch (A-5), render failures contained to a
  counted drop + per-player telemetry containment (A-6), residual-bounded
  entity/stop sampling (A-7), activate/close idempotence + interrupt escalation
  (A-8), GapClock backwards-clock reset (A-9), probe rebind on respawn identity
  change (A-10), `withV16Line`/`withV18Line` no longer clobber the MoveTrace diag
  line (B-3, reversed-order pin added). Full findings in the three review-agent
  reports (this session); dispositions all "fixed" except A-7/A-9 marked PLAUSIBLE
  by the finder and fixed anyway (cheap, strictly safer).

- **2026-08-07 (A2 implementation decisions, yield plan §5)**: the "service diag
  block" pair ships as a conditional `Yield:` line (`withYieldLine`, the conditional-
  slot precedent) with counters in `TickDiagnostics` (service-scoped — live-state sums
  collapse on rejoin, the R2-9 lesson); `bytes_withheld_total` is defined as a
  BYTE-TICK PRESSURE INTEGRAL (each withheld tick adds that tick's held queue bytes —
  repeated counting of a held payload across ticks is the point, it measures hold
  pressure, never delivered bytes); the one-shot INFO fires at the first floor send
  (= the plan's "N consecutive fully-yielded ticks" with N = `YIELD_FLOOR_TICKS`);
  pruned positions ride the send-failure drop-report array to the processor's
  `clearDiskReadDone` (the prune runs main-thread, the done-bits are
  processing-thread-owned). Yield plan §5 annotated in the same commit (the pair).
