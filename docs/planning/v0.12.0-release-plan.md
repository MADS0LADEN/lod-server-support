## Phase A — land the stack on main

1. Merge **PR #207**: `gh pr merge 207 --merge --delete-branch`. **The
   `--delete-branch` is load-bearing** (review MAJOR): this repo has
   `deleteBranchOnMerge=false`, and GitHub only auto-retargets a stacked PR's
   base when the base branch is DELETED — without it, step 2 would merge #208
   into the dead feature branch while main silently lacked the summary half
   (and Phase A's sanity build would still pass, since #207 is self-contained).
   Belt: before step 2, verify `gh pr view 208 --json baseRefName` reads
   `main`; if not, `gh pr edit 208 --base main` first.
2. Merge **PR #208** the same way (`--merge`; never squash — the release-flow
   rule, and review records reference these SHAs).
3. Version bump on main: branch `chore/mod-version-0.12.0`, set
   `mod_version=0.12.0` in `gradle.properties`, PR → merge.
4. Post-merge sanity on main: `./gradlew :fabric:build -x runClientGameTest
   :paper:test :neoforge:build` + `python3 scripts/check_soak.py --selftest` —
   and confirm the merged main diff vs the pre-merge branch tip is empty
   (`git diff feat/region-summary-sync..main -- ':!gradle.properties'` after
   the bump) so the "which half landed" failure class is dead.

Order: **26.1 → 1.21.11 → 1.21.1** (closest surface first — with the review's
caveat that the rename sets differ per line, so "each port informs the next"

gate → review → fold**.

   `chore: bump mod_version to 0.12.0` (review: the bump is a dedicated
   per-line commit by precedent — the main bump is NOT in the pick range, and
   skipping it re-enters the stale-dev-banner state v0.11.1 paid to fix; the
   pre-flight's explicit `-Pmod_version` masks the gap, so nothing else reds).

   don't trust this doc). Non-mechanical resolutions get a note in the port
   commit body. **Must-carry note:** commit 502dd13e (move-trace shutdown
   classload gate) rides the stack unrelated to any feature — it is NOT
   optional and nothing reds if dropped.
3. **Adapt — the hazard checklist** (audited against the actual diff):
   - **MC symbol renames, per line** (compile-caught, but budget them):
     `serverboundPlay()`→`playC2S()` on BOTH 1.21.11 and 1.21.1 (fabric

     `.x` on both 1.21.x; `Identifier`→`ResourceLocation` + the ByteBuf

     line-neutral (verified); the per-line hazard is the REGION-DIR RESOLVER

   - **Channel registration twins**: three new channels — census **10 → 13**

     the ~20-line split-world-dir flavor — re-apply the staging additions

   - **Docs**: line banners/tier framing are KEEP-OURS; port the architecture
     paragraphs only (the v0.11.1 "restore the line banner" commits are the
     cautionary precedent).
4. **Parity check (new — review MAJOR, risk lens):** scripted, before review:

5. **Gate (tier-appropriate)**:

     `:fabric:runClientGameTest` locally before pushing or budget the CI
     triage; a T3 red on a port is a real signal, not a skip.
   - 1.21.1: full builds + T1/T2 + NeoForge contract suite + the 8-test
     gametest smoke + `warm-rejoin-summary` on Fabric **and on
     `SOAK_PLATFORM=paper`** (review: its Paper twin carries the largest

6. **Review — 1-Fable + 3-Opus per line** (user directive), handed the

     the regressions they name; censuses re-scoped to the line's counts).
   Fold verified findings before starting the next line.
7. **Fold + push** the line branch; watch its CI (incl. T3 where present).

  belt is the guard against the silent-half-merge failure; never squash,
  never rebase.
- **Line drift is the schedule risk, concentrated in the Paper twin** — the
  B.0 pins + the parity check + the per-line panels are sized for exactly
  that file.
- **The store exists on all three support lines** (verified: 8 store files
  per v0.11 tip). The store-ARMED rung path gets its per-line exercise via
  the `SOAK_LODSTORE_OVERRIDE=full` wrs run (§C.5); the store-LESS path is
  covered by the default smoke set (all its configs pin `lodStore: "off"`).
- **Credentials**: archon token checked at Phase B step 5; MODRINTH_PAT at
  Phase D step 1 — each immediately before the step that needs it.
- **The demo-video side quest is parked** — nothing here depends on it; the
  Phase B rig deploy replaces the dev jar it was using.
