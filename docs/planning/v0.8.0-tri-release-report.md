## The v0.8.0 delta (forward-ported from the backport review rounds, PR #51)

1. **X-ray mask palette repack** (`XrayMaskFilter.mask()` + Paper twin): the old
   `maskCopy`/`maskInPlace` wrote replacements through `set()`, which never prunes the palette —
   every hidden state's id still shipped in the container bytes (`write()` sends the palette
   verbatim), so a modified client could read the ore list back out of "masked" data. Masked
   sections are now REBUILT into a container seeded on the (never-hidden) replacement via the
   public `PalettedContainer(T, Strategy)` ctor + `PalettedContainerFactory.blockStatesStrategy()`
   — the final shape after the final-review round corrected PR #51's `recreate()` version (see
   below: `recreate()` smuggles the source's palette entry 0 back in). Pinned by
   `maskedSectionPaletteCarriesNoHiddenStates` AND `maskedPaletteDropsTheRecreateSeedResidue` on
   both platforms. Goldens regenerated per line (each pair byte-identical across modules; main
   4138 B, was 6196 B pre-repack).
2. **Paper engine-adoption height floor** (`PaperXrayMaskManager`): section-floors adopted
   `maxBlockHeight` exactly as Paper's engine ctor does (`(h>>4)<<4` — adopting the raw value
   masked up to 15 blocks the near view shows real). Pinned in `PaperXrayMaskManagerTest`.
   (PR #51 also adopted the engine's replacement-block union in OBFUSCATE modes; the final
   review showed that to be a regression and PR #53 reverted it — see below.)
3. **Folia/Paper pre-registration drop fix** (the bug found by the v0.7.3 Folia soak matrix —
   `paper-dirty-falling-block` A1 run-start violation, deficit exactly one `WANT_SET_BUDGET` of
   800): the handshake used to reply SessionConfig inline (region thread on Folia) while
   `enqueueRegister` waited for the pump's drain, so the client's first want-set could land in
   the pre-registration gap and drop uncounted. A REGISTERING handshake's reply is now a
   `Runnable` deferred through `enqueueRegister(player, caps, replyAfterRegister)` and run by
   `drainLifecycleMailbox` immediately after `registerPlayer`. Reply-only outcomes (NO_CONSUMER,
   disabled advertisement) still reply inline; a register racing shutdown discards its reply.
   Pinned in `LSSPaperPluginGlueTest` (registering paths must NOT send inline, both dialects)
   and `PaperRequestProcessingServiceTest` (reply observes registered state; never fires
   post-shutdown). Live-validated: the 1.21.11 Folia `paper-dirty-falling-block` soak — the
   diagnosis scenario — passes with 0 violations on the fixed build.
4. **VoxyCompat type-agnostic slider read**: `unreflectGetter().asType(double)` tolerates Voxy
   changing `sectionRenderDistance` between float/double/int (both shipped Voxy jars declare
   `float` today — this is future-proofing, not a live bug).
5. **NBT disk-path factory memo**: single-slot `PalettedContainerFactory` memo per

## The release-blocking find: `*+` is an invalid GitHub tag-filter pattern (PR #52)

GitHub's workflow filter-pattern language treats `+` as a quantifier, so any pattern containing
`*+` is unparseable. This affected ALL THREE lines: main's (new) `'!v*+mc*'` exclusion and the
support branches' `v*+mc26.1*` / `v*+mc1.21.11*` scoped triggers (authored with the v0.7.3
backports). Observable: **every push created a phantom failed `release.yml` run with zero jobs**
("this run likely failed because of a workflow file issue") — and, decisively, **a real tag push
would have triggered NOTHING**: all three v0.8.0 tags would have published nothing, silently.
The v0.7.3 prep missed it because the phantom runs sat beside green `build.yml` runs and no tag
was ever pushed.

Fix (all three lines, same shape): the trigger glob drops the `+` (`['v*']` on main,
`['v*mc26.1*']` / `['v*mc1.21.11*']` on the branches — `*` swallows the literal `+`), and the
exact scoping moved to a **first-step shell guard** (before checkout), where `+` is plain text:
main refuses `*+mc*` tags; each branch refuses anything that is not its own `v*+mc<line>*`.
`ReleaseWorkflowContractTest` on each line now pins the new trigger, **bans `*+` in any tag
filter**, and requires the guard to precede checkout.

Verified empirically: pushes of the broken files phantom-failed (main run 30236473350, 26.1 run
30237087891); pushes of the fixed files produce **no** release.yml run at all (branch pushes) —
on all three lines.

## Final review round (three Opus agents, one per branch, on the v0.8.0 deltas)

Verdicts: **no blockers on any line**; two MAJORs in the v0.8.0 delta itself, found and fixed
before sign-off (PR #53); the merges/flavors/goldens/scoping on both support branches verified
clean in exhaustive per-file diffs against main.

**MAJOR 1 — the palette repack was incomplete (found independently by the main and 1.21.11
agents).** `PalettedContainer.recreate()` seeds the fresh container with the SOURCE palette's
entry 0 (verified by bytecode on all three lines: `new PalettedContainer<>(palette.valueFor(0),
strategy)`), and the public ctor registers the seed in the new palette where it survives with
zero referencing cells. Vanilla's `pack()` orders saved palettes by first cell occurrence, so
entry 0 is the block at section-local (0,0,0) — a hidden corner block therefore still shipped
its id, at an exactly-known coordinate (the agents proved the unreferenced-seed residue by
decoding the committed goldens: `bits=4, palette=[air, deepslate], referenced=[1]`). Fixed by
seeding the rebuilt container on the (never-hidden) replacement via the public
`PalettedContainer(T, Strategy)` ctor + `PalettedContainerFactory.blockStatesStrategy()` (both
verified present on all three lines); `mask()` now takes the factory (the NBT path already held
it; the live path shares the same weak-keyed memo). New pin on both platforms —
`maskedPaletteDropsTheRecreateSeedResidue` — builds an ore-seeded source container (the exact
disk shape that leaked; the previous pin's factory-built sections always had an air seed and
could not catch it). Goldens regenerated a second time: 4138 B (was 6188) — fully-masked
sections now pack as single-value palettes, which is the fix's visible signature.

**MAJOR 2 — the OBFUSCATE-mode replacement-block union (this round's own earlier "parity"
change) was a regression, reverted.** The main agent verified the premise against Paper's
controller source (modes 2/3 do obfuscate the replacement list — stone/oak_planks/deepslate by
default) but showed the consequence is wrong for LOD masking: with stone+deepslate in the mask,
`needsMasking`'s palette fast-path is constant-true for essentially every underground section
(a per-serve 4096-cell rebuild everywhere), and `chooseReplacement`'s fallback ladder can pick
a state that is itself masked (an all-stone+ore section has no non-hidden candidate),
flattening underground LOD to a single block while violating the no-hidden-states invariant.
Adoption is back to hidden-list-only (the v0.7.2 shipped semantics); the section-boundary
height floor from the same change stays (that part was correct). The `EngineConfig` record
returned to its 3-field shape.

**MINORs fixed:** lifecycle-drain per-event containment (a throwing register no longer aborts
the drain, and a register that published state before throwing still runs its deferred
SessionConfig reply — without this the client sat SessionConfig-less until the v16 discovery
timer degraded the session); factory memos hold their `RegistryAccess` key weakly (integrated-
server registry pin); the support lines' notes gained the two missing v0.8.0 bullets (Voxy
future-proofing, disk-read overhead); the 1.21.11 `ChunkDiskReader` comment kept a stale claim
the merge should have taken from main (corrected); notes wording on main (experimental-Folia
label, "Paper 26.1.2" qualifier on the 26.1 pointer, honest Voxy/disk-read claims); support-line
notes fold the palette fix into the masking feature bullet (masking is NEW on those lines — no
released support-line build ever leaked).

**Accepted as documented (not fixed):** the positional (not structural) guard-step pin in
`ReleaseWorkflowContractTest`; `onNonV16Handshake` running one tick later for REGISTER outcomes
(contained by drain-before-`tickV16Compat` ordering; clients never upgrade mid-session); the
mask rebuild's higher per-section cost vs the old copy-and-poke (bounded: `needsMasking` gates
it to ore-bearing sections only, now that MAJOR 2 is reverted); the 26.1 branch's shared-doc
26.2 references (pre-existing, covered by the CLAUDE.md banner disclaimer); PREV_TAG compare
links on first-of-line tags anchoring to mainline history (cosmetic, by design of the

## Live-test find: AntiXray mode-2/3 adoption flattened LOD terrain (PR #58)

The user's live eyeball on a mode-3 AntiXray server (the exact open-risk this report carried)
surfaced black LOD faces. Root cause: the mod's `obfuscateGlobal` marks EVERY toObfuscate
state true, and modes 2/3 bake in the hidden ∪ replacement union (stone/deepslate/dirt/sand
on real configs) — LSS's auto adoption masked all natural terrain below the cutoff and
`chooseReplacement` flattened each section to its dominant NON-masked survivor (sculk in the
deepslate band = the black faces; water/grass elsewhere). Present since v0.7.2 on mode-2/3
servers (the v0.7.2 gate measured adoption/crash health, not visuals). Fix: the probe
discriminates the controller subclass — Hide (mode 1) adopts as before; Obfuscate/
ObfuscateLayer yield `EngineView.ReplacementNoise` and the manager masks the LSS
`xrayHiddenBlocks` list at the ENGINE's height (`antixray-mod+lss-list`), the same
hidden-list-only decision the Paper side took in the final review. New pins: the probe rung,
the manager rung, and `MaskedWireRoundTripTest` (the diagnosis first PROVED the wire
innocent — masked serves keep light alignment and change only hidden cells — that proof is
now a permanent test). Cherry-picked to both support branches; all suites + pre-flights
re-run green on all three lines. NEEDS the user's visual re-check on the same server.

## Live-test find 2: boundary sky light (PR #59, user-verified fixed)

The user's follow-up report — long-standing black leaf/terrain faces at chunk borders,
previously blamed on Voxy — was trace-diagnosed with the new `/lss trace` `col_light`
instrument: both serve paths dropped air-only sections unless block-lit, so vanilla's stored
boundary sky layers (the light grid spans heightmap+1) never reached the consumer, and faces
sampling that never-ingested air shade black at some LOD mips. Two-sided fix: the server
serves sky-lit air sections banded to content±1 (disk/live parity preserved; light-only NBT
cap entries parse as all-air; block-lit air keeps its unconditional serve; clears stay
clears), and the client fills absent sections above each column's served top with implicit
full-bright sky (vanilla's own above-heightmap rule; covers tall-cliff borders beyond the
stored band). Pinned in NbtSectionSerializerTest (the old `airOnly_skyLightOnly_dropped`
pin was the bug — deliberately inverted) + ClientColumnProcessorTest + MaskedWireRoundTripTest.
Validated: Tier 1/2/3, fabric fresh-backfill (one environmental A7 timeout red on the loaded
box, per-catalog re-run PASS on idle), Paper fresh-backfill, fabric warm-rejoin (the resync
air-fill interaction), Folia smokes on both branches, and the user's visual re-check.
